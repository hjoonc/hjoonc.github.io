## 들어가기 전

이 글은 **개발자도 알아야 할 소프트웨어 테스팅 실무**를 읽으며 공부한 내용을 정리한 글이다.

개인적인 학습 정리인 만큼 일부 내용이 정확하지 않을 수 있으며, **ISTQB 시험을 준비한다면 교재를 직접 읽어보는 것을 추천한다.**

## 1. SDLC 모델의 예
- 순차적 개발 모델 : 폭포수 모델, V모델
- 반복적 개발 모델 : 나선형 모델, 프로토타이핑
- 점진적 개발 모델 : 통합 프로세스

## 2. 소프트웨어 개발 주도를 위한 테스팅 (아래 방법 모두 자동화 테스트로 유지 가능)
- 테스트 주도 개발(TDD) : TC를 통해 코딩 주도, TC작성->코드 작성->리팩토링
- 인수 테스트 주도(ATDD) : 인수 조건에서 테스트 도출, 테스트는 앱 영역 개발 전 작성
- 행위 주도 개발(BDD) : 앱 기대 동작을 이해하기 쉽도록, 자연어로 작성 //Given, When, Then

## 3. 데브옵스(DevOps)와 테스팅
데브옵스는 개발(테스팅 포함)과 운영 협력해 공통된 목표를 달성, 조직 차원의 접근법

## 4. 시프트-레프트 접근법
조기 테스팅 원리, 테스트를 SDLC 초기에 수행하도록 하는 접근법(Shift-Left). 후기를 무시하라는 뜻은 X.

보통 비기능 테스트는 후반에 수행하나, 시프트-레프트에선 컴포넌트 테스트부터 수행.

## 5. 회고 및 프로세스 개선
회고는 프로젝트나 반복 주기가 끝날때, 릴리즈 마일스톤에서 또는 필요시 진행 가능.

회고의 시기는 SDLC 모델에 따라 달라짐. 테스트 완료 보고서에 포함됨.

## 6. 테스트 레벨(단,통,시,인)
- 단위 테스팅 : 컴포넌트를 개별적으로 테스팅. 하네스 또는 프레임워크 등 지원 수단 필요.
- 통합 테스팅 : 컴포넌트 간 인터페이스, 상호작용 테스팅. 상향,하향,빅뱅 등 여러 접근법. //접근법 상세 내용
- 시스템 테스팅 : 전체 시스템, 실제와 유사. 전반적인 동작 기능에 중점. 기능+비기능.
- 시스템 통합 테스팅 : 다른 시스템 또는 외부 서비스와 테스트 대상 간 인터페이스 테스트.
- 인수 테스트 : 밸리데이션과 배포 준비, 필요사항 충족 확인. 알파, 베타 테스팅. //알파:공장, 베타:실제고객

## 7. 테스팅 유형
- 기능 테스트 : 수행해야하는 기능 평가 //무엇을
- 비기능 테스트 : 시스템이 얼마나 잘 동작하는지 테스트, 신뢰성·효율성·이동성·유지가능성 //어떻게

## 8. 확인 테스팅과 리그레션 테스팅
- 확인 테스팅 : 문제가 제대로 수정되었는지 확인. 처음 테스트를 수행한 사람이 재수행.
- 리그레션 테스팅 : 수정 사항이 테스트 대상의 다른 부분에 장애를 일으키지 않았는지 확인.

## 9. 유지보수 테스팅
수정사항, 마이그레이션, 단종 등에 대비한 테스팅. 후반임으로 비용이 가장 비싸다.

## 10. 검증 vs 검정
- 검증(verification) : 올바르게? 정적. 초기조건. 결함예방.
- 검정(validation) : 올바른? 동적. 사용자 관점 요구사항. //워크쓰루,인수와 연관.
