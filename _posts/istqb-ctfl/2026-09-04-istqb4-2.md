## 들어가기 전

이 글은 **개발자도 알아야 할 소프트웨어 테스팅 실무**를 읽으며 공부한 내용을 정리한 글이다.

개인적인 학습 정리인 만큼 일부 내용이 정확하지 않을 수 있으며, **ISTQB 시험을 준비한다면 교재를 직접 읽어보는 것을 추천한다.**


## 0. 블랙박스 테스트 기법
- **동적 테스팅**
- 내부 코드 구조 고려 X, **명세 기반**
- 테스트 기법 : **동·경·결·상·유**

아래에서는 각 테스트 기법의 개념과 특징을 간단히 정리한다.

## 1. 동등 분할
- 입력 데이터를 동일하게 처리될 것으로 예상되는 분할(Partition) 단위로 나누는 기법.
- 각 분할에서 대표값을 선택하여 테스트 케이스를 구성.
- 커버리지 항목 = 각 분할
- 커버리지 = TC실행 분할수/식별 분할수 * 100

## 2. 경계값 분석
- 동등 분할의 경계값을 기반으로 테스트하는 기법.
- 경계가 존재하는 정렬된 분할(Ordered Partition)​에 적용 가능.
- 경계값과 경계값 주변에서 결함이 발생할 가능성이 높다는 점을 이용.

## 3. 결정 테이블 테스팅
- 조건(Condition)​과 그에 따른 동작/결과(Action)​를 테이블로 표현.
- 비즈니스 규칙처럼 여러 조건이 서로 영향을 주는 복잡한 논리를 테스트하는 데 효과적.
- 가능한 조건 조합을 체계적으로 도출하여 누락된 경우를 찾을 수 있음.
- 중복되거나 불가능한 조합을 제거하여 테스트 케이스를 최적화할 수 있음. (ex. 주행과 충전은 동시 발생 불가)
- 조건이 많아질수록 조합의 수가 급격히 증가하여 시간과 노력이 많이 필요할 수 있음.

## 4. 상태전이 테스팅
- 가능한 상태와 유효한 상태 전이를 표시해 시스템 동작을 모델링.
- 상태(state),전이(transition),이벤트(event),가드(guard[]),액션(action/)
- 상태전이 테스팅은 상태전이 다이어그램 필요.
- 테스트 순서 반드시 외울것 (테/트/반/무/가케/프)
  - 상태-이벤트 테이블 구성
  - 전이 트리 구성
  - 반응(legal) 또는 유효(valid) TC 구성
  - 무반응(illegal) 또는 비유효(invalid) TC 구성
  - 가드(guard) 또는 조건 TC 구성
  - 테스트 프로시져(Test procedure) 구성
- 다음과 같은 상태 전이 다이어그램을 바탕으로 TC 테이블 작성할 수 있음.

## 5. 유즈케이스 테스팅
- 사용자가 시스템을 이용하여 목표를 달성하는 전체 흐름을 기반으로 테스트하는 기법.
- 기본 흐름(Basic Flow)​뿐만 아니라 대체 흐름(Alternative Flow) 및 예외 흐름​도 테스트.
- 여러 기능이 연결된 전체 시나리오 및 사용자 관점의 동작을 검증하는 데 효과적.
- 유즈케이스에 정의되지 않은 동작이나 세부 조건은 테스트에서 누락될 수 있음.
