## 들어가기 전

이 글은 **개발자도 알아야 할 소프트웨어 테스팅 실무**를 읽으며 공부한 내용을 정리한 글이다.

개인적인 학습 정리인 만큼 일부 내용이 정확하지 않을 수 있으며, **ISTQB 시험을 준비한다면 교재를 직접 읽어보는 것을 추천한다.**

## 0. 화이트박스 테스트 기법
- **동적 테스팅**
- 내부 코드의 구조와 로직을 고려, ​**구조 기반**
- 주요 구조 커버리지 : **구·결·조·조결·변·다·경**

아래에서는 각 테스트 기법의 개념과 특징을 간단히 정리한다.

## 1. 구문 커버리지
- 테스트 스위트에 의해 실행된 실행 가능한 구문(statement)​이 전체 실행 가능한 구문의 몇 퍼센트인지를 측정하고 평가.
- 100% 구문 커버리지 : 실행 가능한 모든 구문이 최소 한 번 이상 실행됨.

## 2. 결정 커버리지
- 테스트 스위트(suite, 묶음)에 의해 실행된 **결정의 분기 결과(True / False)가 전체 가능한 분기의 몇 퍼센트**​인지를 측정하고 평가.
- **​결정 테스팅**​ = **​분기 테스팅**​. 결정 커버리지를 높이기 위해 각 결정의 분기를 실행하도록 테스트 케이스를 도출하는 기법.
- 100% 결정 커버리지 : 모든 결정의 가능한 분기가 최소 한 번 이상 실행됨.
- 100% 결정 커버리지를 달성하면 100% 구문 커버리지도 자동으로 달성된다.
- 제어 흐름 테스팅 : 프로그램의 실행 흐름과 분기 구조를 기반으로 테스트, 주로 단위/통합 테스트에서 사용됨.
  - 순환 복잡도(Cyclomatic Complexity) = 결정 지점 수 + 1 (일반적인 단일 연결 구조 기준).
  - 독립적인 실행 경로의 수를 파악하고 테스트 케이스를 설계하는 데 활용됨.
 
## 3. 조건 커버리지
- 개별 조건식이 참/거짓 모든 값을 가지게 되면 달성.

![ISTQB Condition Coverage](/assets/img/posts/istqb/pic4-3-1-conditioncoverage.png)

## 4. 조건/결정 커버리지
- 결정과 조건 커버리지를 최소한 조합으로 달성.

![ISTQB Condition Coverage](/assets/img/posts/istqb/pic4-3-2-conditiondecisioncoverage.png)

## 5. 변형 조건/결정 커버리지
- 각 개별조건식이 다른 개별조건식에 영향을 받지 않고 전체 조건식의 결과에 독립적으로 영향을 주도록 함.
- 가능한 한 의미있게 조합의 수를 줄여 테스트 수행.

![ISTQB Condition Coverage](/assets/img/posts/istqb/pic4-3-3-modifiedconditiondecisioncoverage.png)

## 6. 다중 조건 커버리지
- 결정 포인트 내 모든 개별 조건식의 모든 가능한 논리적 조합 고려하여 100% 커버리지 보장.
- 출시 전 모든 결함을 제거해야하는 테스트에서 주로 사용.

![ISTQB Condition Coverage](/assets/img/posts/istqb/pic4-3-4-multipleconditioncoverage.png)
