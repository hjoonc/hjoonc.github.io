## 들어가기 전

이 글은 **개발자도 알아야 할 소프트웨어 테스팅 실무**를 읽으며 공부한 내용을 정리한 글이다.

개인적인 학습 정리인 만큼 일부 내용이 정확하지 않을 수 있으며, **ISTQB 시험을 준비한다면 교재를 직접 읽어보는 것을 추천한다.**

## 1. 테스트 개발 프로세스 : 컨디션 -> 케이스 -> 프로시져
- 테스트 컨디션 : 테스트 대상의 기능, 품질속성, 트랜잭션 등 테스트 설계 필요 대상 or 조건
- 테스트 케이스
- 테스트 프로시져 : 테스트 케이스의 실행 순서

## 2. ISO/IEC 9126 소프트웨어 품질 특성 표준 (기.사.신.효.유.이)
제 2장의 "기능/비기능 테스트"와 관련됨.
- 기능성 : 요구되는 기능을 만족
- 사용성 : 사용자가 이해하고 배우기 쉬운 정도.
- 신뢰성 : 규정 성능 수중 유지. 결함 방지.
- 효율성 : 자원의 적절한 사용 및 적절한 반응시간 정도.
- 유지보수성 : 수정 및 변경의 용이성
- 이식성 : 다양한 환경에서 운영될 수 있는 능력.

## 추가
- 발견하지 못했던 결함을 가장 많이 발견한 TC가 효과성이 높은 TC이다.
- 네거티브 테스팅 : 청개구리 테스팅, 일부러 원하지 않는 행동을 하는것.
- 테스팅 프로세스는 개발 프로세스와 연계해 정립해야한다.
- 하네스 = 테스트 대상이 실행되는 환경을 시뮬레이션 (스텁, 드라이브) //제 2장의 "테스트 레벨"과 관렴됨.

## 3. 테스트 설계 기법의 종류
- 블랙박스 테스트 기법 (명세 기반, **동적**) : 내부 구조를 참조하지 않음. 동적 분석 기반. (동.경.결.상.유)
- 화이트박스 테스트 기법 (구조 기반, **동적**) : 테스트 대상의 내부 구조와 처리 분석. (구.결.조.조결.변.다.경)
- 경험기반 테스트 기법 : 테스트의 지식과 경험을 활용 (오.탐.체)
