## 0. 경험 기반 테스팅
- 테스터의 **경험, 직관, 지식 및 기술적 역량**​을 바탕으로 테스트 케이스(TC)를 도출하는 기법.
- 공식적인 테스트 기법만으로 발견하기 어려운 **특수한 상황이나 결함을 찾아내는 데 유용**하며, 다른 테스트 기법과 함께 활용할 수 있음.
- 테스터의 경험과 역량에 따라 **테스트의 효과성과 일관성이 달라질 수 있음.**
- 비교적 **빠르게 테스트를 설계하고 수행할 수 있으며,** 공식적인 테스트 수행 이후 보완적으로 활용되기도 함.

아래에서는 주요 경험 기반 테스트 기법의 개념과 특징을 간단히 정리한다.

## 1. 오류 추정
- 테스터의 **지식과 경험을 바탕으로 오류, 결함 또는 장애가 발생할 가능성이 높은 부분을 예측**​하여 테스트하는 기법.
- **과거에 결함이 자주 발생했던 영역이나 실수하기 쉬운 부분**을 중심으로 테스트 케이스를 도출.

## 2. 탐색적 테스팅
- 상세한 테스트 케이스를 사전에 작성하기보다 **테스트 설계, 실행, 학습을 동시에 수행하는 접근법.**
- 테스터의 **경험, 직관 및 발견 능력을 적극적으로 활용**​하여 테스트를 수행.
- **테스트 차터**​를 기반으로 테스트의 목적과 범위를 정하고, 정해진 시간 동안 집중적으로 수행.
- 테스트 수행 중 발견한 내용과 결과를 **간략하게 기록**하고, 수행 후 결과를 요약하여 공유.
- 다른 경험 기반 테스팅과 달리 **차터, 시간 제한, 결과 기록 등 일정한 구조를 갖추어 수행​**할 수 있음.
- **구성요소 (차.노.박.회)**
  - **테스트 차터(Test Charter)**
    - 테스트할 **대상, 방법, 중점적으로 확인할 사항** 등을 정의한 테스트 지침.
    - 각 테스트 세션의 **목적과 범위**를 명확하게 설정.
  - **테스트 노트(Test Note)**
    - 테스트를 실행하면서 **계획·설계·테스트 케이스 도출을 동시에 수행**하고 그 내용을 기록.
    - **실행 결과, 발견한 결함 및 특이사항** 등을 기록하여 테스트 수행 내용을 남김.
  - **타임 박싱(Time Boxing)**
    - 일정 시간 동안 테스트에 집중할 수 있도록 **수행 시간을 제한**하는 방식.
    - 일반적으로 **60~120분 정도의 세션**으로 수행하며, 집중력과 일정 관리에 도움.
  - **회고(Debriefing)**
    - 테스트 종료 후 **발견한 결함과 특이사항, 테스트 수행 결과를 요약하여 보고.**
    - 테스트 과정에서 얻은 **경험과 지식을 공유하고 문서화.**

## 추가사항. TC 기반 테스팅 vs 탐색적 테스팅 비교
- **TC 기반 테스팅**
  - **요구사항 및 설계 문서를 기반**으로 테스트 케이스를 사전에 작성.
  - **TC 작성 → 실행** 순서로 진행하며, 테스트 실행 및 관리에 중점을 둠.
  - **사전에 설계된 TC를 기반으로 테스트를 수행.**

- **탐색적 테스팅**
  - 테스터의 **경험과 지적 능력**을 적극적으로 활용.
  - **TC 설계와 실행을 반복**하면서 테스트를 점진적으로 발전시킴.
  - 테스트 과정에서 얻은 정보를 다음 테스트에 반영하는 **점진적·주기적 방식**으로 수행.

## 3. 체크리스트 기반 테스팅
- 테스터의 **경험과 노하우를 체크리스트 형태로 정리**하여 테스트하는 기법.
- 체크리스트의 항목을 기반으로 **확인해야 할 사항을 빠짐없이 점검**하며 테스트 수행.
- 상세한 테스트 케이스보다 **구체성과 체계성이 낮을 수 있으며,** 테스터의 경험과 역량에 영향을 받음.

## 4. 기타 비공식 테스트 기법 
### 분류 트리 기법
- 테스트 대상의 입력이나 조건을 **분류(Classification)하고 각 분류의 선택지(Class)를 트리 형태로 표현**하는 기법.
- 분류된 항목을 조합하여 **테스트 케이스를 체계적으로 도출**할 수 있음.
- 공식적인 명세 기반 테스트 기법에는 포함되지 않는 **비공식 테스트 설계 기법**.

## 5. 테스트 설계 기법 선택
- 테스트 설계 기법은 **리스크 수준(Risk Level)을 포함한 여러 요소를 고려하여 선택**한다.
- **리스크가 높은 영역일수록 더 철저하고 강도 높은 테스트가 필요**하며, 여러 테스트 기법을 조합하여 적용할 수 있음.
